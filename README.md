# Лабораторна робота №4 — варіант 3

## Generics, колекції та власний репозиторій

У роботі реалізовано параметризований `GenericRepository<T>`, функціональний інтерфейс `IdentityExtractor<T>`, перевірку дублікатів, логування через SLF4J і тести на JUnit 5.

Репозиторій працює з `Book`, `Reader`, `BookLoan` та `Author`. Для кожного типу використовується окрема identity-лямбда. Дані авторів завантажуються з `data/authors.csv`, де є коректні, некоректні та дубльовані записи.

Для зберігання використано `LinkedHashMap<String, T>`. Вона забезпечує пошук за identity у середньому за сталий час, унікальність ключів і зберігає порядок додавання елементів. Метод `findAll()` повертає копію списку, тому зміни результату не впливають на репозиторій.

## Порівняння пошуку в Map і List

Benchmark виконується для 100 000 читачів. Час наведено в наносекундах, для кожного сценарію взято мінімальне значення після прогріву JVM.

| Сценарій | Map, ns | List, ns |
|---|---:|---:|
| Перший елемент | 41 | 83 |
| Останній елемент | 41 | 815792 |
| Відсутній елемент | 41 | 817667 |

Пошук у `Map` майже не залежить від позиції елемента. Лінійний пошук у `List` найкращий для першого елемента, але для останнього і відсутнього проходить майже весь список, тому різниця стає великою.

Benchmark запускається класом `ua.library.repository.SearchBenchmark`.
